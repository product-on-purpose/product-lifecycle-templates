## The finding, which is the circularity signature

**A positive rubric gap beside a negative held-out gap is exactly the pattern threat T1 predicted, and it
is worse than the null it warned about.** T1 is rubric circularity: the treatment arm has read the answer
key, so it can win by mentioning rubric items rather than by being better. The threat list lives in the
2026-07-10 audit's measurement-validity pass, which is maintainer-local and not tracked here; the mitigations
it prescribes are restated in [the eval protocol](../../docs/internal/eval-protocol.md).

The treatment arm wins by 0.62 on criteria drawn from the template's own guide, and loses by 0.81 on
criteria drawn from neither. Read plainly: **the template moves effort into the sections it asks for and
away from usefulness it does not ask for.**

The judges' unprompted notes say the same thing more concretely. On the same scenario, one judge wrote of
the treatment document:

> no explicit stop or kill condition anywhere in Risks or Rollout, probe 2 is unanswerable from this
> document

and of the control document:

> the only one of the three with an explicit, named Stop condition section, and the only one with a
> dedicated Ownership section naming who validates the rest-day rule, both held-out criteria the rubric and
> guide never teach, so their presence here is a real signal

## A confound this run introduced, stated because it changes the reading

**The control-arm prompt names several of the held-out criteria, and the templates do not.**

Version 1 of `control-prompt.md` instructs the control arm to "distinguish what you were told from what you
concluded" and to "name the risks and the unknowns". Two of the held-out criteria are
`decision_vs_information_distinguishable` and a stop-or-kill condition. Those are close to the same
instruction.

So the negative held-out gap is **not clean evidence that templates suppress decision-usefulness.** A large
part of it is that the control arm was told to produce decision-usefulness and the treatment arm was not.

That does not make the finding disappear. It sharpens it: **these held-out properties are cheaply learnable
from one sentence of instruction, and the templates do not contain that sentence.** A template that costs a
reader more effort than a paragraph of generic advice, and produces less of what makes a document
decision-useful, has a problem that is about the templates rather than about the measurement.

**Fixing this is a protocol change, not a template change, and it comes first.** Until the control prompt
and the treatment instruction are matched for how much decision-usefulness each names, the held-out gap
cannot be attributed.

## Every other limit of this run

- **Six scenarios, one generation per arm.** The spec calls for two generations to damp sampling variance.
  This run has none of that damping, so the per-scenario numbers carry more noise than the table suggests.
- **No bootstrap interval.** The protocol requires the gap to be reported with one, and with too few
  scenarios to compute a meaningful interval, the point estimates above are the honest maximum.
- **Three bundles of twenty-six.** Nothing here generalises to the library.
- **No human anchor.** The judge scale is unanchored, so absolute scores mean less than the gaps between
  arms.
- **Judge and generation model are the same family**, which the protocol allows and flags. A different
  judge model for one seat is the standard mitigation and was not used.
- **The held-out criteria were authored by agents that had read the templates**, because proving absence
  required searching them. That is the right way to prove absence and the wrong way to stay independent.

## The harness bug worth recording

**The first execution produced 33 valid judgments and zero aggregated rows.** Every judge returned real,
detailed scores. The un-blinding map was keyed on the label `A`, and judges echoed the heading they had
been shown and returned `Artifact A`. Every lookup missed, every arm aggregated over an empty set, and the
summary reported all three arms as null.

**The gates failed closed, which is the only reason this is a footnote rather than a false result.** With
no data at all, the run reported `discrimination: FAIL` and `controlSanity: FAIL, control drifted to a
strawman` rather than a passing gate over an empty set. A harness that reported "no findings, all clear" on
zero rows would have been indistinguishable from a real null.

The aggregation now matches on the trailing letter and **logs a warning naming any verdict it cannot
un-blind**, because a silent miss turns a completed run into a null that looks like a finding. Fixed in the
same file; the 33 agents replayed from cache, so the numbers above are from the original judgments and were
not re-generated after the fix.

## What happens next, in order

1. **Match the arms for decision-usefulness instruction.** Control-prompt v2, or a treatment instruction
   that names as much. The held-out gap is uninterpretable until this is done, and it is the cheapest fix
   here.
2. **Re-run the pilot** on the same six scenarios. Same scenarios, so the change in the gap is attributable
   to the prompt change and nothing else.
3. **Only then decide whether the templates have a real problem.** If the held-out gap stays negative with
   matched instruction, that is a finding about the bundles, and per this library's own honest-number rules
   it gets published and acted on rather than buried.
4. **Do not scale to 26 bundles until the pilot produces an interpretable gap.** Scaling an instrument that
   returns void is how a large number gets built on a small mistake.
