# product-lifecycle-templates v0.28.0

Release date: 2026-11-25. This project follows [Semantic Versioning](https://semver.org/). This is a minor
release with one new bundle. Nothing was removed or renamed, so nothing you use today breaks.

## Summary

**You can now write a competitive analysis.** It says who else serves the customers your strategy chose,
compares them on what those customers value, and says what that means for the product's direction. You keep it
as a series of dated versions, adding one at each refresh, rather than rewriting it. It is the library's 59th
bundle.

## New

- **`competitive-analysis`, in lean and full sizes.** Lean names the competitor set, with the status quo counted
  among the alternatives, profiles each rival, and compares them on weighted criteria drawn from what customers
  value. An evidence table gives each claim its source and the source's date. The findings end in moves, each with
  an owner and a date, and a refresh trigger says what event prompts the next version. Full adds a short brief for
  each main rival and a scorecard rated against the customers' jobs.
- **It joins `strategy-docs` as its eighth member**, a `utility`, by
  [ADR 0091](../internal/decisions/0091-competitive-analysis-joins-strategy-docs-as-an-eighth-member.md). In the
  family's chain it sits just before the positioning statement. Its worked example is Acme Analytics' analysis for
  the segment the product strategy chose, with fictional rivals.
- **The family contract says what the example owes its siblings** (`strategy-docs` 0.5.1). It may find that a
  sibling's claim is too broad, but it must name that claim and send it to the sibling's owner. The example does
  this once, for a claim in the positioning statement.

## Improved

- **The positioning statement names its new place in the chain** (`positioning-statement` 0.1.1). Its chain
  comment had said "third", which was stale.
- **The build cost is published.** The competitive analysis cost $15.99 at API list rates, for 17 agents, in
  [`bundle-builds/INDEX.md`](../../bundle-builds/INDEX.md).

## Fixed

- **The competitive analysis's guide could pass a document whose findings led to no moves, or whose refresh
  trigger could never fire.** A 0 on either rubric row now fails the document whatever its total. The bundle moves to 0.1.1, after a Codex review whose 13 findings
  were each checked against their sources before they were applied.
- **Several source readings were corrected.** Three were misread: Klue's refresh cadence for product teams,
  Blank's stance on feature charts, and how many publishers count the status quo as an alternative. Each now
  matches its cached page.

## Known issues

- **Neither skill's description names competitive analysis yet.** An agent decides whether to load a skill from
  its description, so a request worded only as "competitive analysis" may not reach either skill. Both
  descriptions sit at the 1,024-character cap, and which phrase gives way is the maintainer's decision. The bundle
  is still found through `manifest.json` and the MCP server's `search_templates`.
- **Nothing here makes any bundle better.** All 59 are `beta`, and no page calls one proven.
- **No filled-in, published competitive analysis was read.** The bundle's section set rests on vendor and
  consultancy guidance, and most of those vendors sell competitive-intelligence software. Its history says so.
- **The efficacy evidence still supports no quality claim, in either direction.** Of five runs, four were void.
  The latest one's below-zero result sits on a measure the protocol does not gate on, and that measure was chosen
  for what the templates lack, which biases it against them.
- **A search filtered to one axis value can be cut short.** The MCP server's `search_templates` returns at most 8
  candidates, and `utility` now holds 13 bundles, `deliver` 10, `foundation` 10 and `develop` 9. `total_matched`
  in the response tells you when a list was cut.
