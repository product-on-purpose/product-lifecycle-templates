# product-lifecycle-templates v0.18.0

Release date: 2026-10-15. This project follows [Semantic Versioning](https://semver.org/).

## Summary

**The library grows from 44 bundles to 45 with a data dictionary: the standing reference to what each field
in a dataset or table means.** When two teams read a field's meaning from the same dictionary, they can
compute the same number from it. This release also makes both agent skills name every document type the
library builds, so an agent asked for one of the newer types can find the skill that fills it.

The new bundle is not proven to help anyone. It is researched, and it says where its sources disagree.

## New

- **[`data-dictionary`](../../templates/data-dictionary/)** - the standing reference to what the fields of a
  dataset or table mean. Lean carries a purpose and boundary section, a field definitions table, and an
  ownership and review section. Each table opens with its grain and its key. Each field row gives the type
  and nullability, the definition, the allowed values and missing codes, the source, the sensitivity and the
  owner. Full adds dataset metadata, the relationships between tables, validation rules, and a review and
  sign-off section. It is the seventh `governance-docs` member, and it is a standing reference rather than a
  document tied to one lifecycle phase.

## Improved

- **Both agent skills now name every document type the library builds.** Their descriptions named the 25
  Tier-1 types and `rfc`, and none of the eighteen other Tier-2 types built by `v0.17.0`. An agent decides
  whether to load a skill from its description, so a request for a tracking plan or a business continuity
  plan might never have reached either skill.
- **The fill skill no longer says that every bundle has a full variant.** 41 of the 45 bundles have one, and
  the other four ship a single size.
- **Every quotation in the data dictionary's research log was checked against the source's raw text**: 333
  quotations from 46 sources.
- **The data dictionary's catalog entry now says what the document is for.** It states field meaning as the
  purpose, drops "metric definitions" and "data catalog entry" as aliases, and adds "codebook". The tracking
  plan gains "event dictionary" as an alias, so a search for the list of product-analytics events finds it.
- **Each release now checks its documentation for three audiences.** The release process lists the pages
  that users, technical readers and agents read, and two checks for pages that a release left stale.

## Fixed

- **GitHub release pages no longer open with raw YAML.** 19 of the 21 release pages from `v0.1.0` to
  `v0.17.0` showed the release note's frontmatter as plain text above the title. Each page was edited to
  remove the frontmatter and nothing else, and the release process now removes it before publishing.

## Known issues

- **Nothing here makes any bundle better.** All 45 are `beta`, and no page calls one proven.
- **The data dictionary leaves metric formulas to the KPI dashboard, and three of its sources disagree.**
  Those sources put a metric's calculation inside the data dictionary. This library keeps formulas in
  `kpi-dashboard`, and the data dictionary's companion labels that split as the library's own position.
- **One search can still not list a whole phase.** The MCP server's `search_templates` returns at most 8
  candidates, and the `deliver` phase holds 9. `total_matched` in the response tells you when a list was cut.
- **Build cost is measured, not a rate.** At API list rates, the data dictionary cost $17.72 for the whole
  build, across 16 agents ([`bundle-builds/`](../../bundle-builds/INDEX.md)).
