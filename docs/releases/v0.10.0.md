# product-lifecycle-templates v0.10.0

Release date: 2026-09-21. This project follows [Semantic Versioning](https://semver.org/).

## Summary

**If you installed the MCP server and it never worked, this is the release that fixes it.** The
server could not start from a `git clone` and had not since it shipped: the path in `.mcp.json` used
a variable Claude Code sets only for plugin installs. The server itself was fine the whole time.

The same server now speaks a **typed response envelope**. Every tool returns `{ok, data?, error?}`,
and responses arrive as `structuredContent` rather than JSON text a caller has to re-parse. **This is
a breaking change** for anything written against the older shapes.

The library also stops publishing a real-fill count. Every bundle is still `beta`, and no page will
call one proven.

## New

- **Typed responses.** All five MCP tools declare an output schema, so a caller receives
  `structuredContent` instead of parsing a text field. `error` carries a closed `code` enum
  (`no_such_bundle`, `no_such_variant`, `unknown_part`, `no_such_file`, `no_guide`, `strip_failed`)
  alongside the hint fields refusals already carried.

## Changed

- **The MCP wire format, breaking** ([ADR 0054](../internal/decisions/0054-the-mcp-server-returns-a-uniform-envelope.md)).
  `ok` now means **the call completed** and never a domain verdict. A document that fails validation
  is `ok: true` with `data.valid: false`; a strip refusal is `ok: true` with `data.refused: true`. The
  word used to mean three different things at once, which would have rendered an invalid document as
  `{"ok": true, "data": {"ok": false}}`.
- **A bundle that ships no requested part** now reports `{present: false, reason: ...}` inside
  `data.parts` rather than a nested `error`, because that is a fact about the bundle and not a caller
  mistake.
- **The zero-fills disclosure is retired**
  ([ADR 0055](../internal/decisions/0055-retire-the-zero-fills-disclosure.md)). The site, the README,
  `AGENTS.md` and `STATE.md` no longer publish a fill count, and the rule gating `stable` on "one real
  usage cycle" is replaced by the maintainer's judgement that a bundle has settled. **The ban on
  calling a bundle proven, verified or validated is unchanged** and remains enforced on every page.

## Fixed

- **The MCP server could not start from a clone.** `.mcp.json` located it with
  `${CLAUDE_PLUGIN_ROOT}`, which is set only for a plugin-provided config; opened as an ordinary
  project the variable is absent and the path never resolved. Now
  `${CLAUDE_PLUGIN_ROOT:-.}/tools/mcp_server.py`, which works both ways.
- **Three stale documentation facts**: two Tier-2 bundles listed as unbuilt that shipped in `v0.8.0`,
  a refused type recorded as merely unbuilt, and an install doc quoting 58 template variants when
  there are 63.

## What this release does not prove

- **A working server is not a used server.** Nothing outside this repository has driven it, and no
  assertion scores whether its search ranks well. The test suite says so in its own summary.
- **Retiring the fill disclosure changed what is published, not what is known.** No bundle was
  promoted; all 30 remain `beta`; the four efficacy runs still stand as the only measurement, the most
  recent finding the probe gap at exactly 0.00.
- **Two defects this release fixed were both invisible to green checks**, and for the same reason:
  each was verified through a path no real caller uses. The server was proven by a script that
  bypassed its config; the envelope was designed against an in-process spike that skipped the output
  validation a real client performs. Both passed everything that was looking.
- **The `mcp<2` pin still stands.** Whether the SDK's v2 handles return annotations identically is
  unverified, and the port is not scheduled.
