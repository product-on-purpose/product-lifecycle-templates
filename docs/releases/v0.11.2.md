# product-lifecycle-templates v0.11.2

Release date: 2026-09-22. This project follows [Semantic Versioning](https://semver.org/).

## Summary

**The build-cost numbers published in `v0.11.0` were about twice the truth, and this release corrects
them everywhere they appeared.** A whole bundle build costs about **10M to 12M weighted
token-equivalents**, not 21M to 25M. That is **$33 to $41 at Anthropic API list rates**, a figure every
report now states beside the weighted total.

If you read a cost from `bundle-builds/`, the runbook, the build command or `STATE.md` before today,
halve it. No template, bundle, MCP tool or install route changed.

## New

- **Every build-cost report now says what the build would cost in dollars.** Each API response is
  priced at its own model's list rate, and the report breaks that down by stage, by model and by
  deliverable, next to the weighted total. It answers "what did this cost?" directly, where the
  weighted unit never could: a weighted token on Opus costs more than one on Sonnet. The price table
  is dated and sourced, and a model it does not list is shown as unpriced, never as free. It prices
  the work rather than billing it: work run under a Claude subscription is not charged per token.

## Improved

- **[`bundle-builds/README.md`](../../bundle-builds/README.md) now explains what the two numbers
  are.** The weighted total is a fixed unit for comparing reports; the dollar figure is what the same
  work would cost at list rates. It also states how a response is counted, and why a wrong generator
  could ship wrong reports with every check green.

## Fixed

- **Build costs were overstated by 1.9 to 2.6 times, in every report.** The generator counted each
  API response two or three times. The harness writes one transcript record per content block of a
  response (its thinking, its text, each tool call), and every record repeats the response's full
  usage, which the generator added up record by record. All 22 reports are recounted from the same
  transcripts. **Which agents belong to which bundle did not change at all**; only the counts did.

  | Build | Was | Now | At API list rates |
  |---|---:|---:|---:|
  | `test-summary-report` | 24,650,553 | **12,123,040** | **$41.22** |
  | `spike-report` | 20,743,317 | **9,881,764** | **$33.21** |

- **Three conclusions drawn from those numbers.** The old estimates of 0.6M to 1M tokens were low by
  roughly 10 to 20 times, not 20 to 30. The four-lens review is not "under half of research": it is
  67 percent of it on one build and 54 on the other. Cache reads are about half the weighted cost,
  not a tenth. **Drafting is still the most expensive stage**, and in dollars it is over two thirds of
  each build, because its agents ran on Opus while the rest ran on Sonnet.
- **Every report claimed the orchestrator's own spend was reported per session in the index. It was
  not reported anywhere**, and each report now says so.

## Changed

- **The build-report format is version `2.0.0`.** Every count is per API response rather than per
  transcript record, so the `turns` field now means responses. Anything reading the old `1.0.0`
  numbers was reading figures about twice too high; no report remains in that format.

## Known issues

- **The cost measurement still rests on two whole builds.** The other twenty reports are marked
  `floor`, meaning "at least this much", and will stay that way because their transcripts cannot be
  relabelled.
- **Why drafting ran on Opus is still unexplained.** The build workflow pins Sonnet on every stage,
  yet the five drafting agents in the measured builds resolved to Opus. Their records carry no
  requested model at all. The next bundle build will show whether it recurs, and its report will be
  the first whole build attributed exactly.
- **CI still cannot check a report against its source.** The transcripts are local to the machine that
  ran the build, so a wrong generator can ship wrong reports with every check green, which is how
  this defect shipped. [ADR 0056](../internal/decisions/0056-build-cost-is-measured-and-ingestion-is-separate-from-verification.md)
  accepted that weakness and now carries a dated Correction pricing it.
- **Nothing here makes any bundle better.** Every one is still `beta`, and no page calls one proven.
  A cost is not a quality.
