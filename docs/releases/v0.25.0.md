# product-lifecycle-templates v0.25.0

Release date: 2026-11-07. This project follows [Semantic Versioning](https://semver.org/). This is a minor
release with one new bundle. Nothing was removed or renamed, so nothing you use today breaks.

## Summary

**You can now keep a requirements traceability matrix.** It is the standing table that links each requirement
to the tests and other evidence that verify it, so a requirement with no verification can be seen. It is the
library's 55th bundle. Its guide starts with who should not keep one, because this bundle's research found no
software team outside regulated or safety-critical work that describes keeping one.

## New

- **`requirements-traceability-matrix`, in lean and full sizes.** The lean size gives each requirement one row,
  with its source, what verifies it and its status. It also lists the requirements nothing verifies and the tests
  no requirement asks for. The full size adds each requirement's design and code references, a trace from each
  risk to the requirement that controls it, and dated snapshots of the matrix. The worked example is an
  unregulated team. Its matrix pairs a permissions requirement with the tests that check it, which no other
  document did, because the requirement had no identifier.
- **It joins `governance-docs` as the family's eighth member**, as a standing document consulted repeatedly
  rather than written once, by
  [ADR 0084](../internal/decisions/0084-requirements-traceability-matrix-joins-governance-docs-as-an-eighth-member.md).
- **It states no regulation's requirements.** Standards and regulator guidance are cited only to show the
  practice exists. The catalog places this type at Tier 3. The maintainer accepted the reading that the library's
  standing "no" to Tier-3 regulated content does not reach a bundle that carries no regulation text.
- **Every claim traces to a source.** The research log records 22 sources, each fetched and checked, with every
  quotation compared against the page's raw text.

## Improved

- **Both skills now recognize a request for a traceability matrix.** An agent decides whether to load a skill
  from its description, so a type missing from it may never reach the skill. No existing trigger was removed.
- **The build cost is published for two bundles.** The traceability matrix cost $10.92 at API list rates for 15
  agents, and the Lean UX Canvas, held back from `v0.24.0`, cost $17.52, both in
  [`bundle-builds/INDEX.md`](../../bundle-builds/INDEX.md). The traceability matrix ran on a model whose cache
  reads cost half as much, so compare its weighted total, not its dollars, with earlier builds.
- **The business case guide names what a new-product case should add.** That paragraph replaces a separate
  opportunity assessment, which was declined by
  [ADR 0086](../internal/decisions/0086-product-opportunity-assessment-is-declined.md). A manager user guide was
  also declined, by [ADR 0085](../internal/decisions/0085-manager-user-guide-is-declined.md).
- **One more site is on the list research agents may not read.** First Round Review's terms bar crawling, so
  the build runbook now lists it.

## Fixed

- **The build-cost report generator billed a multi-candidate sweep to one bundle.** A run that judged five
  candidates was counted into the Lean UX Canvas. A run whose labels name two or more candidates now counts
  toward no build.
- **The generator priced a build on a new model at $0.00.** Its price table now lists that model, and every
  other row was re-checked against Anthropic's pricing page, with no price changed.

## Known issues

- **Nothing here makes any bundle better.** All 55 are `beta`, and no page calls one proven.
- **Nothing read shows that keeping a traceability matrix improves outcomes.** The bundle says so, and its lean
  and full split is a hypothesis, because no published template carries every link type.
- **The efficacy evidence still supports no quality claim, in either direction.** Of five runs, four were void.
  The latest one's below-zero result sits on a measure the protocol does not gate on, and that measure was chosen
  for what the templates lack, which biases it against them.
- **A search filtered to one axis value can be cut short.** The MCP server's `search_templates` returns at most 8
  candidates, and `deliver` holds 10 bundles, `utility` 12 and `develop` 9. `total_matched` in the response tells
  you when a list was cut.
