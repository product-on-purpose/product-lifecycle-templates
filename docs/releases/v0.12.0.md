# product-lifecycle-templates v0.12.0

Release date: 2026-09-23. This project follows [Semantic Versioning](https://semver.org/).

## Summary

**The library grows from 30 bundles to 31 with a launch coordination checklist**: the standing list a
team consults before it ships an externally visible change, so that readiness does not depend on who
happens to be asking the questions.

If you ship changes other teams have to support, this is the new template. If you are deciding how far
to trust this library, the useful news is how its research was checked: **every quotation in the new
bundle's research log was compared with the source's own text, and 19 of 193 were not there.** They were
removed before anything was written from them.

## New

- **[`launch-coordination-checklist`](../../templates/launch-coordination-checklist/)** - grouped
  readiness checks, each with an owner, a go/no-go gate decided in advance, and a rollout plan with the
  condition that reverses it. Lean for an engineering readiness list; full adds who holds decision
  authority and who must be told before, at and after the launch. It pairs with the pm-skills
  `deliver-launch-checklist` skill: the skill produces the copy filled for one launch, and this is the
  standing list that copy is made from.
- **It rests on a source, not a guess.** Appendix E of Google's *Site Reliability Engineering* book is
  titled "Launch Coordination Checklist", the type's own name. The book's chapter on launches also
  settles the question of whether such a list is kept or written fresh each time: "In 3.5 years, one LCE
  ran 350 launches through the LCE Checklist."

## Improved

- **The bundle teaches the practice around Google's list, not the list itself.** The appendix is licensed
  CC BY-NC-ND 4.0, which forbids derivatives, and describes one company's infrastructure "circa 2005". So
  no section of the template adapts its items, and the companion presents it as the origin of the type
  rather than as current practice.
- **Research quotations are now checked against the page, not against a tool's summary of it.** The
  research tool returns a model's summary of a page, and quotations lifted from a summary can be altered
  or invented. One of the 19 removed quotations invented a patient's identity inside the quotation
  marks. The check now runs before a research log is written.

## Fixed

- **Counts that had drifted beside correct markers**, some for several releases: the gate explainer
  quoted 94 self-test assertions against 104 and 20 research logs against 25, and `library.json` said "26
  of the 27" bundles ship a full variant.
- **The review stage that checks a worked example against its sibling examples was never given the
  siblings.** It now reads the examples its bundle cites. The build workflow also now sends a Tier-2
  type to the spec file that actually holds its section design.
- **The `release-notes` bundle stops listing the launch checklist as a future template**, because it
  exists.

## Known issues

- **One build is not a rate.** This bundle cost $14.22 at API list rates to build, every agent on
  Sonnet, and is the first build measured end to end with every agent attributed. The next build will
  show whether that figure is typical.
- **A quotation that is on the page can still be attached to the wrong claim.** The new check proves a
  quotation's words exist in its source, not that the source supports the sentence citing it. That is
  still the adversarial review's job.
- **The fix to the sibling-example review is unexercised.** It changes a prompt, and only the next
  build's review will show whether the stage now reads what it should.
- **Nothing here makes any bundle better.** All 31 are `beta`, and no page calls one proven.
