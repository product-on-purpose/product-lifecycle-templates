# product-lifecycle-templates v0.11.1

Release date: 2026-09-22. This project follows [Semantic Versioning](https://semver.org/).

## Summary

**Nothing user-facing changed shape in this release.** No template, no bundle, no MCP tool and no
install route is different. What changed is what this repository says about itself, and in three
places it was saying something untrue.

The largest single gap: **the library published a website and never told a human reader it exists.**
`README.md`, `CONTRIBUTING.md` and all four Diataxis directories carried zero mentions of it. The
technical documentation was already strong and the agent-facing note was already correct. The human
lens was simply absent.

## New

- **[`docs/explanation/the-site.md`](../explanation/the-site.md)** - how the published site is
  generated, guarded and deployed: the four inputs, the five guards and where they run, and the
  honesty gate's three conditions. A `README.md` callout now links the live site, and
  [`bundle-pipeline.md`](../internal/bundle-pipeline.md) Phase 6 tells a bundle author that their
  content gets published and that the honesty gate can fail `site.yml` even when `run-gate.py` is
  green.
- **[ADR 0056](../internal/decisions/0056-build-cost-is-measured-and-ingestion-is-separate-from-verification.md),
  the decision `v0.11.0` shipped without.** It records why ingestion and verification are separate
  commands, and the consequence that looks wrong from outside and is deliberate: the CI gate checks
  an index it can re-derive and never the build-cost reports it cannot, because the transcripts are
  machine-local. A report here is trusted because it was generated once, not because it can be
  re-derived. That is weaker than every other generated artifact in this repository and is now
  stated rather than implied.
- **Work package WP-55**, retrofitting the build-cost work into the roadmap the way WP-51 and WP-53
  were.

## Changed

- **This repository stated a wrong reason for a right decision, and the correction is left visible.**
  `site.yml` said the all-in-one `withastro/action` "runs astro build directly with no pre-build hook
  and would skip the generator entirely". It does not: its build step runs the package manager's
  `build` script, which fires `prebuild` and therefore the generator, exactly as this workflow does.
  Verified against the action's own `action.yml`. The real reason to refuse it is better and is the
  one the guards exist for: **that action bundles the artifact upload into itself**, leaving no seam
  between the build and the upload, which is precisely where every guard has to run.

## Fixed

- **[ADR 0055](../internal/decisions/0055-retire-the-zero-fills-disclosure.md)'s cleanup was
  incomplete, in the two most visible places in the project.** That record stopped publishing a
  real-fill count "on any public surface", and its own table enumerated **prose** - so the README's
  `real fills - 0 (honest)` badge survived it, through the same blind spot `check-counts.py`
  documents about badge URLs. The live landing page also still promised "until a real usage cycle is
  recorded", a graduation rule that same record had replaced. Both removed.
- **The live landing page claimed the library spans six families.** It has **nine**, and had since
  the page shipped. Nothing could have caught it: that page is `.mdx`, which sat outside the
  prose-count gate's file glob, and `<!-- -->` is not a comment in MDX. The gate now reads
  `{/* counts: */}`, scans `.mdx`, and carries a `families` fact. Mutation-tested.
- **Twenty further stale claims**, including `STATE.md` reporting twenty-seven bundles under the
  heading "Built and true today" when its own generated marker nine lines above said thirty, README
  family tables missing four bundles that shipped in `v0.8.0`, and a companion describing a sibling
  bundle as unbuilt weeks after it shipped.

## What this release does not prove

- **Nothing here makes any bundle better.** Every one is still `beta`, and no page calls one proven.
  This release corrected what the library says; it did not change what the library is.
- **The measured build cost still rests on two whole builds.** The other twenty reports are marked
  `floor` and will stay that way, because transcripts cannot be relabelled retrospectively.
- **One measurement remains unexplained.** `build-bundle.js` pins `sonnet` on every stage, verified
  against the file as it stood at the measured build. That build shows the five drafting agents
  resolving to `claude-opus-5` anyway, while research and review, pinned identically, resolved to
  sonnet. The cause is not established, and the next build will show whether it recurs.
