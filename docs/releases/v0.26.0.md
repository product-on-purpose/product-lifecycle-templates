# product-lifecycle-templates v0.26.0

Release date: 2026-11-13. This project follows [Semantic Versioning](https://semver.org/). This is a minor
release with one new bundle. Nothing was removed or renamed, so nothing you use today breaks.

## Summary

**You can now keep a platform and device support matrix.** It is the standing page that says which browsers,
operating systems and devices a product supports, at what grade, and which of them the team actually tests on.
It is the library's 56th bundle. Teams consult it when they choose test browsers, triage a bug from an unusual
browser, or decide whether a polyfill is owed.

## New

- **`platform-device-support-matrix`, in one lean size.** It has seven sections: purpose and scope, support
  grades, the matrix itself, the threshold rule by which a browser enters or leaves the matrix, what an unsupported browser
  gets, who owns the page, and the event that makes it wrong. The guide separates two meanings of "support" that
  the sources run together: what a user on a browser gets, and what the team tests. The worked example is a
  fictional ferry-booking site.
- **It joins `standing-standards` as the family's eighth member**, as a `foundation`, a page agreed once and
  consulted repeatedly, by
  [ADR 0088](../internal/decisions/0088-platform-device-support-matrix-joins-standing-standards-as-a-foundation.md).
  The catalog gains entry 212 for the type.
- **Every claim traces to a source.** The research log records 36 sources. The admission named four that publish
  such a matrix, led by the GOV.UK Service Manual and GOV.UK Frontend's browser support grades.

## Improved

- **Both skills now recognize a request for a browser or device support matrix.** An agent decides whether to
  load a skill from its description, so a type missing from it may never reach the skill. No existing trigger was
  removed. Two sentences that are not triggers were shortened to make room under the length cap.
- **The project brief guide names what a brief for a discovery effort should add.** That paragraph replaces a
  separate product discovery plan, which was declined by
  [ADR 0087](../internal/decisions/0087-product-discovery-plan-is-declined.md).
- **The build cost is published.** The support matrix cost $11.55 at API list rates for 16 agents, all on
  Sonnet 5.5, in [`bundle-builds/INDEX.md`](../../bundle-builds/INDEX.md).

## Fixed

- **The README described every bundle as eight files.** A single-size bundle ships seven, with no full template.
- **The README misstated what the research found on review triggers.** It now names the four
  `standing-standards` members whose sources name a condition that should prompt a review.
- **Several counts outside the gated markers had gone stale.** The README now says the catalog holds 212 types,
  the MCP server addresses 108 template variants, and thirty Tier-2 types are built.

## Known issues

- **Nothing here makes any bundle better.** All 56 are `beta`, and no page calls one proven.
- **Nothing read shows that keeping a support matrix improves outcomes.** The bundle says so in its guide and
  companion, and no source read measures what keeping one costs.
- **The efficacy evidence still supports no quality claim, in either direction.** Of five runs, four were void.
  The latest one's below-zero result sits on a measure the protocol does not gate on, and that measure was chosen
  for what the templates lack, which biases it against them.
- **A search filtered to one axis value can be cut short.** The MCP server's `search_templates` returns at most 8
  candidates, and `deliver` holds 10 bundles, `utility` 12 and `develop` 9. `total_matched` in the response tells
  you when a list was cut.
