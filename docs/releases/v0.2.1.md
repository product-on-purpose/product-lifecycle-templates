# product-lifecycle-templates 0.2.1

**Released 2026-08-08.** This project follows [Semantic Versioning](https://semver.org/).

> **This page was written on 2026-08-09, after the fact.** Every other release note here was written as
> part of its own release. This one was not, and saying so is cheaper than letting a reader assume
> otherwise. The gap was found on 2026-08-09 while cutting `v0.3.1`: the inventory in
> [`docs/releases/README.md`](README.md) listed three pages for four releases.
> [`release-process.md`](../internal/release-process.md) names a release note as one of **four** required
> artifacts per release, so its absence was a real gap against this repository's own process, not a
> stylistic one. Nothing in this note is reconstructed from memory: it is drawn from
> [the changelog entry](../../CHANGELOG.md) and the release commit, both written at the time.

## Summary

**This release exists because the previous one was tagged before its downstream contract was read.**

`v0.2.0` shipped the complete Tier-1 floor and the library's first user-facing documentation. The
intention was to list it in the Product on Purpose plugin registry. Reading that registry's listing
contract at that point, rather than before, surfaced **clause L3**: a repository with no root
`library.json` is "loose components" under the Advanced Skill Library Standard and **is not eligible for a
new listing**. This repository had none.

**A published tag is not moved.** `v0.2.0`'s tree could not come to contain a file created after it was
tagged. So the fix is this release: add the manifest, re-cut, and pin that.

**If you use the library, nothing here changes for you.** No template, no bundle, and no documentation
moved. This release matters only to how the library is distributed.

## New

- **A root [`library.json`](../../library.json)**, binding the Advanced Skill Library Standard at version
  `0.12` and declaring conformance at tier **universal (Bronze)**. This is the file that makes the
  repository a *library* under the Standard rather than a collection of loose components, and it is what
  the registry requires before it will list anything.
- **The tier was measured, not declared.** The Standard ships its own conformance gate, and it was run
  against this repository rather than reasoned about: it exits 0 at universal, and prints the remaining
  findings that belong to the convergent tier above the declared ceiling. Declaring a tier without running
  the gate would have been this library's own dominant defect, committed into a governance registry.

## Improved

**None in this release.** No template, bundle, guide, example, research log or documentation page changed.

## Fixed

- **The library could not be listed anywhere, and did not know it.** Listing clause **L3** blocks a new
  listing for a repository with no `library.json`, and clause **L4** requires the pinned commit to sit on
  a release tag whose tree carries that file, with the registry entry, the tag, `library.json` and every
  native manifest all reading the same version. `v0.2.0` satisfied neither. Both are satisfied here, and
  `.claude-plugin/plugin.json` was bumped to `0.2.1` for the same reason.

## Security

**No security-relevant changes in this release.** No dependency changed.

## Known issues

As of this release, and none of them fixed by it:

- **Template quality was unmeasured.** At `v0.2.1` there were no efficacy evaluations at all. The first
  ones ran on 2026-08-08 and are reported in [`v0.3.0`](v0.3.0.md); both returned VOID.
- **No template had been filled by anyone but the author**, which remains true.
- **The `npx skills add` route was broken in a way nobody had discovered yet.** At this release it
  installed the maintainer-internal build harness alongside the real skill, and delivered a skill without
  the library it indexes. **Neither was known on 2026-08-08**, because the install had never been run.
  Both are described and fixed in [`v0.3.0`](v0.3.0.md). This is stated here rather than quietly omitted:
  anyone still pinned to `v0.2.1` through that route has both defects.

## Upgrading

**Nothing here is breaking**, and there is no reason to pin to this release. It is superseded by
[`v0.3.0`](v0.3.0.md) and [`v0.3.1`](v0.3.1.md), and the install defects above are reasons to move off it
rather than reasons to stay.

The skill's name changed in `v0.2.0`, from `product-lifecycle-templates` to `plt-fill-template`. That
rename is carried by this release and is unchanged since.

## The lesson this release paid for

Recorded in [`release-process.md`](../internal/release-process.md) as step 2, and worth repeating because
the cost was exactly one extra release:

**When work crosses a governance boundary, the receiving system's contract is an input to your build, not
a checklist you satisfy at the end.**
