# product-lifecycle-templates v0.24.0

Release date: 2026-10-30. This project follows [Semantic Versioning](https://semver.org/). This is a minor
release with two new bundles. Nothing was removed or renamed, so nothing you use today breaks.

## Summary

**You can now write two one-page canvases.** The Lean UX Canvas frames one initiative before anyone commits to
building it. The Lean Canvas states a whole product's business model as beliefs to test. They are the library's
53rd and 54th bundles, and each ships one size, because each originator publishes the canvas as one page.

## New

- **`lean-ux-canvas`, Jeff Gothelf's Lean UX Canvas.** It frames one initiative: the business problem, the
  outcomes the business wants, the users and the outcomes they want, candidate solutions, and the hypotheses that
  link them. It then names the most important thing to learn first and the least work that would learn it. A
  ninth section records each dated revision and names the document that takes over. Gothelf renamed the canvas
  the Lean Product Canvas in 2024, and the bundle accepts that name too.
- **`lean-canvas`, Ash Maurya's Lean Canvas.** It states a product's business model on one page: the customer
  segments and early adopters, their problems and how they solve them today, the unique value proposition, the
  solution, channels, revenue streams, cost structure, key metrics and unfair advantage. Two further sections,
  the library's own addition, name the riskiest beliefs to test next and keep a dated record of each version.
- **Each canvas sits in an existing family.** The Lean UX Canvas joins `discovery-docs` at the `discover` phase,
  by [ADR 0082](../internal/decisions/0082-lean-ux-canvas-joins-discovery-docs-at-discover.md). The Lean Canvas
  joins `strategy-docs` as a standing document revised as its beliefs are tested, second in the chain between the
  product vision and the product strategy, by
  [ADR 0083](../internal/decisions/0083-lean-canvas-joins-strategy-docs-as-a-seventh-member.md).
- **Every claim in both bundles traces to a source.** The Lean UX Canvas's research log records 19 sources, and
  the Lean Canvas's records 15. Each also draws on a book or PDF the maintainer supplied from their own copy,
  which is quoted briefly and never committed.

## Improved

- **Both skills now recognize a request for either canvas.** An agent decides whether to load a skill from its
  description, so a type missing from it may never reach the skill. No existing trigger was removed.
- **The template chooser lists every bundle.** Its family table was missing the Lean Canvas and the user
  research report; it now lists all 54.
- **The build cost is published for the Lean Canvas.** It cost $22.96 at API list rates for 16 agents, in
  [`bundle-builds/INDEX.md`](../../bundle-builds/INDEX.md). The Lean UX Canvas's report is held back, because the
  report generator counted an earlier admission sweep into its totals.
- **Three more sites are on the list research agents may not read.** Strategyzer, Tability and the Wade
  Institute studio forbid automated reading in their terms, so the build runbook now lists them.

## Fixed

- **The unfair-advantage definition is credited to Jason Cohen.** Both of Maurya's pages quote it under Cohen's
  name, and the Lean Canvas bundle now does too.
- **"The lean canvas" in the product vision guide is clarified.** It means that bundle's own short canvas format,
  not Maurya's Lean Canvas, and a dated note now says so.

## Known issues

- **Nothing here makes any bundle better.** All 54 are `beta`, and no page calls one proven.
- **The efficacy evidence still supports no quality claim, in either direction.** Of five runs, four were void.
  The latest one's below-zero result sits on a measure the protocol does not gate on, and that measure was chosen
  for what the templates lack, which biases it against them.
- **A search filtered to one axis value can be cut short.** The MCP server's `search_templates` returns at most 8
  candidates, and `deliver` holds 10 bundles, `utility` 11 and `develop` 9. `total_matched` in the response tells
  you when a list was cut.
