# product-lifecycle-templates v0.20.1

Release date: 2026-10-22. This project follows [Semantic Versioning](https://semver.org/). This is a patch:
no bundle was added, and no MCP tool or install route changed.

## Summary

**The problem statement bundle now answers to its right names.** A search for a "point of view statement"
finds it. A search for an "opportunity statement" no longer does, because the maintainer ruled that the two
are different documents.

The release also records what the library plans to build next. A design brief is specced, and a new check
keeps future document types aimed at software product teams.

## New

- **A design brief is planned as the next `define` bundle.** It hands the chosen problem, and the one concept
  chosen for design, to the people who will design it. It never specifies how that concept works. The spec
  and [ADR 0079](../internal/decisions/0079-design-brief-joins-discovery-docs-at-define.md) (design-brief joins
  discovery-docs at define) set two sizes, lean and full. The bundle itself is not built yet.
- **The library now asks who writes a document before admitting it.** A candidate type needs one named source
  showing a software product, UX or technology team writing or using it, wherever the document began. A
  candidate that fails only this check waits for evidence instead of being declined.
  [ADR 0080](../internal/decisions/0080-admission-gains-a-software-audience-check.md) (a fifth admission check,
  for a software audience) applies to future admissions only, so none of the 49 built bundles changes.
- **The catalog counts 207 types.** The opportunity statement became its own entry, number 207. It is a
  candidate, not a bundle.

## Improved

- **`problem-statement` gains the alias "point of view statement".** The Interaction Design Foundation and the
  Canada School of Public Service both use that name for this document. An agent that searches by that name
  now reaches the bundle. The template moves to 0.1.1.

## Fixed

- **`problem-statement` no longer claims to be an opportunity statement.** Its aliases listed "opportunity
  statement", and its guide, both templates and three companion passages treated the two as one document. The
  maintainer ruled on 2026-10-17 that they differ, and each of those places now says so with the date. **If
  you reached this bundle by searching for "opportunity statement", search for "problem statement" instead.**
  The library has no opportunity statement bundle.

## Known issues

- **Nothing here makes any bundle better.** All 49 are `beta`, and no page calls one proven.
- **Both new decision records were accepted on the maintainer's delegation, without the maintainer's own read
  of their text.** ADR 0079 also amends the `discovery-docs` family contract. The maintainer may change either
  record by a later dated note.
- **One question about the new admission check is still open.** Nobody has ruled whether a source that does the
  same job under another name passes. It will be ruled the first time it changes an outcome.
- **Whether the opportunity statement gets its own bundle is open.** Its admission research began on
  2026-10-22, and the decision waits for the maintainer.
- **A search filtered to one axis value can be cut short.** The MCP server's `search_templates` returns at
  most 8 candidates, and `deliver` and `utility` hold 10 bundles each and `develop` 9. `total_matched` in
  the response tells you when a list was cut.
