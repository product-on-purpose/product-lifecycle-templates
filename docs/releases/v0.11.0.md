# product-lifecycle-templates v0.11.0

Release date: 2026-09-22. This project follows [Semantic Versioning](https://semver.org/).

## Summary

**This library refuses to call a single bundle proven without evidence, and the number it used to
decide whether a bundle was worth building had none.** Two documents stated a per-bundle build cost
and they disagreed: the runbook said "roughly 0.6-1M tokens" and the build command said "roughly
700K-1M". Neither cited a measurement.

The measurement was always available. The Claude Code harness writes a per-agent transcript with a
full usage block on every turn, and nothing had ever read one. This release reads them.

**Measured, the cost is 21M to 25M weighted token-equivalents per bundle** - between 20 and 30 times
the estimates it replaces. That number now lives in [`bundle-builds/`](../../bundle-builds/), is
generated rather than typed, and is gated in CI like every other generated artifact here.

## New

- **`bundle-builds/`, a new top-level directory** holding one build-cost report per bundle per
  `template_version`, as a readable `.md` and a machine-readable `.json`, plus a generated
  [`INDEX.md`](../../bundle-builds/INDEX.md) list view.
  [`README.md`](../../bundle-builds/README.md) states what the numbers are and are not.
- **`tools/gen-bundle-build-report.py`**, which joins three things the harness already writes: the
  run journal that maps each subagent to its label, phase and the file it wrote; the per-agent
  transcript that carries the model and the usage; and the per-agent sidecar that carries the
  requested model tier. Each report breaks a build down **by stage, by resolved model, by requested
  tier and by deliverable**.
- **22 backfilled reports**, covering every bundle whose transcripts still exist on the machine that
  built them.
- **A 32nd CI step**, "Build-report index freshness".

## Changed

- **Both cost estimates are replaced by the measurement**, in
  [`bundle-pipeline.md`](../internal/bundle-pipeline.md) and in the build command. The runbook also
  claimed the cost was "dominated by research fan-out and the four-lens review"; measured, drafting
  is the largest single stage and the review is under half of research.
- **Every workflow agent label now carries its bundle type.** A label used to read `draft:companion`,
  which says what an agent did but not what it did it for. It now reads
  `test-summary-report/draft:companion`. This costs nothing at runtime and makes attribution exact
  rather than inferred.

## Fixed

- **`STATE.md` said "Twenty-seven bundles" under the heading "Built and true today".** There are
  thirty, and its own generated marker said so nine lines above. It was stale by exactly the three
  Tier-2 bundles that shipped in v0.8.0. The same table was corrected for this defect on 2026-09-15,
  four cells further down; this is its third instance there.
- **`STATE.md` also reported the gate "passing on all 27 bundles".** Thirty.
- **`risk-register`'s companion called `raid-log` "the next governance-docs member to be built".** It
  has been built and shipping for weeks.
- **`bundle-pipeline.md` said the build script runs "its two fan-outs".** It has three stages, and the
  missing one was drafting, which writes seven of the eight bundle files.
- **`README.md` reported the current version as v0.8.0**, two releases behind its own badge.

## What this release does not prove

- **These numbers rank spend and nothing else.** A build that cost more is not a better bundle. Every
  bundle is still `beta`, and nothing here changes what the library claims about quality.
- **Only two of the 22 reports cover a whole build.** The other twenty are marked `floor`, meaning at
  least one fan-out is missing from the total, because those builds predate the labelling convention
  that makes attribution exact. Read a floor as "at least this much".
- **Attribution is `medium` for most reports**, meaning a run was matched to a bundle by consensus
  across its agents' prompts rather than by an exact label. A research run compares its subject
  against a sibling type, so a consensus match can in principle land on the sibling.
- **Reasoning effort is not measured**, because the harness does not record it anywhere. Only the
  requested model tier is.
- **CI cannot verify the reports themselves.** It checks that the index matches the committed
  reports. The transcripts those reports came from are machine-local and absent on the runner, which
  is why ingestion happens at the end of a build rather than whenever someone remembers.
