# product-lifecycle-templates v0.23.0

Release date: 2026-10-29. This project follows [Semantic Versioning](https://semver.org/). This is a minor
release with one new bundle. Nothing was removed or renamed, so nothing you use today breaks.

## Summary

**You can now write a user research report.** It reads out one study of the people a product serves: what the
study found, how that answers each question the plan set, and what to do about it. It is the library's 52nd
bundle. It pairs with the user research plan from v0.22.0, so a study can now be planned and reported with the
same library.

## New

- **`user-research-report`, in two sizes.** Lean asks for a summary, an answer to each research question, what
  the team did, the key findings, and the recommendations. For a usability test it also asks for the tasks'
  results. Full adds the background and objectives, open questions, and an appendix. The report recommends what
  to do next, and it leaves the decision itself to the document that records it.
- **A worked example reads out a real study shape.** It is the readout of the 2026-05 Reporting friction study,
  the same study the user research plan's example plans. That study was a set of interviews, so the example
  marks the usability block as not applicable and says why.
- **Every claim in the new bundle traces to a source.** Its research log records 52 sources. The maintainer read
  two of them by hand, because those sites' terms of use forbid automated reading.
- **The `research-docs` family is complete.** Both of its members, the plan and the report, are now built. Every
  one of the library's eleven families now has all its founding members built.

## Improved

- **Both skills now recognize a request for a user research report**, beside the plan. An agent decides whether
  to load a skill from its description, so a type missing from it may never reach the skill.
- **The user research plan points to its report.** Its example's opening note, which said the report was not
  built, now carries a dated correction and a link to the readout.
- **The spike report's guide names the new bundle for user research.** It already sent an exploration of users,
  rather than of technical feasibility, to an interview-synthesis skill. It now names this library's own document
  for that case too.
- **The build cost is published.** The report's build cost $38.54 at API list rates, for 23 agents, all on
  Sonnet. The figure is in [`bundle-builds/INDEX.md`](../../bundle-builds/INDEX.md).

## Fixed

- **The plugin's description said efficacy had been measured four times.** It has been measured five times, and
  the description now says so, in the same words as `AGENTS.md`.

## Known issues

- **Nothing here makes any bundle better.** All 52 are `beta`, and no page calls one proven.
- **The efficacy evidence still supports no quality claim, in either direction.** Of five runs, four were void.
  The latest one's below-zero result sits on a measure the protocol does not gate on, and that measure was chosen
  for what the templates lack, which biases it against them.
- **A search filtered to one axis value can be cut short.** The MCP server's `search_templates` returns at most 8
  candidates, and `deliver` and `utility` hold 10 bundles each and `develop` 9. `total_matched` in the response
  tells you when a list was cut.
