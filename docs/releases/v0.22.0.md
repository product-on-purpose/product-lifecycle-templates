# product-lifecycle-templates v0.22.0

Release date: 2026-10-26. This project follows [Semantic Versioning](https://semver.org/). This is a minor
release with one new bundle and one new family. Nothing was removed or renamed, so nothing you use today breaks.

## Summary

**You can now write a user research plan.** It is the plan for one study of the people a product serves: why
the study runs, which decision it will inform, what the team must learn, from whom, how, and when. It is the
library's 51st bundle, and the first in a new family for research documents.

## New

- **`user-research-plan`, in two sizes.** Lean asks why the study runs and which decision it informs, the
  research questions, the method, the participants, the schedule, and what happens to the findings. For a
  usability test it also asks for the tasks and the measures, because Nielsen Norman Group notes that such a
  plan "is often referred to as a test plan". Full adds what the team already knows, roles and observers,
  consent, privacy and ethics, and related documents. A worked example plans a set of customer interviews about
  reporting friction.
- **Every claim in the new bundle traces to a source.** Its research log records 37 sources, all read. Each of
  its 473 quotations was checked against the source page's raw text, not against a summary.
- **A new family, `research-docs`, for documents about one study.** It will hold the user research plan and the
  user research report. The report is not built yet.
- **The catalog counts 210 document types.** Entry 210 is the user research plan, with "usability test plan" as
  an alias.
- **The fifth efficacy run is published, and it is not good news.** It ran four scenarios of `acceptance-criteria`
  and `incident-postmortem` and was void on its main test. On criteria drawn from outside each template and its
  guide, documents written with the template scored below documents written without it. Those criteria were
  chosen because the templates lack them, which biases them against the template.
  [The result](../../evals/results/2026-10-23_four-scenario.md) says what it can and cannot show.

## Improved

- **Eight bundles take sourced improvements.** Each change below cites a page that was read and quoted from its
  raw text. Each bundle moves one patch version.
  - `status-report` names an eighth trap: compiling the report at the deadline instead of keeping a draft.
  - `experiment-design-doc` and `experiment-readout` warn that a ratio metric can move opposite to its own
    numerator and denominator, so check both.
  - `kpi-dashboard` compares itself with a North Star Metric, so you can tell which one you need.
  - `project-brief` names Atlassian's Project Poster as the living-document convention it declines.
  - `product-vision` points its `prfaq` and `narrative` formats at SVPG's worked examples.
- **Both skills now recognize a request for a design brief or a user research plan.** An agent decides whether
  to load a skill from its description, and neither type was named there before.

## Fixed

- **Two bundles leaned on sources nobody had read.** `acceptance-criteria` said where acceptance criteria end and a
  Definition of Done begins on the strength of a Scrum.org page that was never retrieved. It now cites Atlassian's
  Definition of Done page, which was read. `user-stories` cited Jeff Patton's print book for story mapping, and it
  now cites his web pages beside it.

## Known issues

- **Nothing here makes any bundle better.** All 51 are `beta`, and no page calls one proven.
- **The user research report is not built yet.** It is the plan's pair, and its build is in progress.
- **The efficacy evidence still supports no quality claim, in either direction.** Of five runs, four were void.
  The latest one's below-zero result sits on a measure the protocol does not gate on, for the reason above.
- **A search filtered to one axis value can be cut short.** The MCP server's `search_templates` returns at most 8
  candidates, and `deliver` and `utility` hold 10 bundles each and `develop` 9. `total_matched` in the response
  tells you when a list was cut.
